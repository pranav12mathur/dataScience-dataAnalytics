1. Create a SQL view named TopRatedRestaurants that selects the restaurant name, average rating, and total number of reviews from a table of Zomato-style restaurant reviews, showing only restaurants with an average rating above 4.0.

  **answers**
  ```
    create view TopRatedRestaurants as
    select restaurant_name, avg(rating) as average_rating, count(review_id) as total_reviews
    from restaurant_reviews
    group by restaurant_name having avg(rating) > 4.0
  ```

2. Update the TopRatedRestaurants view to also include the city column from the original restaurants table by joining the relevant tables.<br><br><em><strong>Hint:</strong> Use an INNER JOIN to combine data from both tables in your view definition.</em>

  **answers**
  ```
    create view TopRatedRestaurants as
    select r.restaurant_name, avg(rr.rating) as average_rating, count(rr.review_id) as total_reviews, r.city
    from restaurant_reviews rr
    inner join restaurants r on rr.restaurant_id = r.restaurant_id
    group by r.restaurant_name, r.city having avg(rr.rating) > 4.0
  ```

3. Try to update the average rating column directly through the TopRatedRestaurants view and observe what error or limitation occurs. Write down the exact error message and explain why this happens based on SQL view limitations.

  **answers**
  When attempting to update the average rating column directly through the TopRatedRestaurants view, we see this error : "ERROR: cannot update a view that contains aggregate functions." This happens because SQL views that include aggregate functions (like avg) are not updatable, meaning you cannot directly modify the data in the view since it is derived from underlying tables and involves calculations that cannot be directly mapped back to individual rows in the source tables.

4. Create a view called DailyOrderSummary that shows, for each date, the total number of food orders and the total revenue from a Swiggy-style orders table. Ensure the view only includes dates from the last 30 days.<br><br><em><strong>Constraint:</strong> Use WHERE and GROUP BY clauses in your view definition.</em>

    **answers**
    ```
        create view DailyOrderSummary as
        select order_date, count(order_id) as total_orders, sum(order_amount) as total_revenue
        from food_orders
        where order_date >= current_date - interval '30 days'
        group by order_date
    ```

5. List 3 good practices you should follow when creating SQL views for analytics dashboards, and for each, give a one-line example related to a Flipkart sales reporting scenario.
   
   **answers**
   
   1. **Use descriptive names for views and columns**: This helps users understand the purpose of the view and the data it contains. For example, a view named "MonthlySalesByCategory" clearly indicates that it contains monthly sales data categorized by product type.
   2. **Include only necessary columns**: This improves performance and makes the view easier to use. For instance, a view for a Flipkart sales dashboard might only include columns like "product_id", "category", "monthly_sales", and "revenue" instead of all columns from the sales table.
   3. **Document the view definition**: Adding comments to the view definition can help other developers understand the logic and purpose of the view. For example, a comment in the view definition for "MonthlySalesByCategory" could explain that it aggregates sales data by month and category to provide insights into sales trends.
